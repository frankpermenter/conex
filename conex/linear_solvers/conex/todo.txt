Tree Solver Refactoring Plan: Structured Subsystem Support
==========================================================

Goal: Exploit the fact that each LinearConstraint contributes A^T W A
(rank m) to its clique. Instead of materializing the dense Gram matrix
and factoring it in O(n^3), keep A and use Woodbury in O(n*r^2).

Current state (done):
- LowRankPlusDiagonalSubsystem: Woodbury factor/solve for D + UU^T
- LowRankDiagonalAdapter: bypasses lazy evaluator, writes d/U directly
- UpdateData() and variables() are virtual on the adapter base class
- Tests: single-clique solve, Schur complement, adapter UpdateData

What exists today that can be removed for the structured path:
  WorkspaceLinear       -- holds W (weights), temps, weighted_constraints
  GramEvaluator         -- computes (WA)^T(WA) block-by-block
  LazySymmetricMatrix   -- interface for block-by-block Gram extraction
  WriteSymmetricLazy    -- contributor writes lazy blocks into subsystem storage
  Constraint::workspace -- only exists for WorkspaceLinear
  owned_workspace_memory_ in Decompose -- allocates WorkspaceLinear buffers

This entire chain exists to materialize A^T W A into dense storage.
With Woodbury, the subsystem holds A directly (as U = A^T) and W
folds into D or into U via sqrt(W)*A.

Remaining work:

1. New Decompose path that keeps A instead of creating LinearConstraint
--------------------------------------------------------------------------
SparseLinearConstraintAssembler::Decompose currently creates
LinearConstraint objects (which allocate WorkspaceLinear, GramEvaluator).

Add an alternative that produces lightweight data holders:

  struct ConstraintBlock {
    MatrixXd A;          // m x n_clique
    VectorXd b;          // m
    vector<int> variables;
  };

Decompose already computes these (the RowGroup struct is identical).
The new path skips LinearConstraint/workspace creation entirely.

2. Tree solver factory: per-clique rank check and subsystem selection
------------------------------------------------------------------------
In MakeTreeSolver, after Decompose:
  For each clique, sum the row counts of all ConstraintBlocks assigned to it.
  total_rank = sum of m_i
  n = supernode size

  if total_rank < n:
    Create LowRankPlusDiagonalSubsystem
    Stack: U = [A1^T | A2^T | ...]  (n x total_rank)
    d = 0 (or regularization)
  else:
    Fall back to current dense path (LinearConstraint + lazy evaluator)

The crossover is automatic. No flags, no per-constraint annotations.

3. UpdateData for the structured path
-----------------------------------------
Each structured clique needs an adapter whose UpdateData() writes
the stacked A^T into the subsystem. Two options:

  a) One LowRankDiagonalAdapter per clique that holds references to
     all ConstraintBlocks for that clique. UpdateData stacks them.

  b) One adapter per ConstraintBlock, each writing into a column range
     of the subsystem's U. Requires the subsystem to pre-allocate U
     with the right total rank.

Option (a) is simpler. The adapter replaces the current per-constraint
KKTAssemblerToSubsystemAdapter + SubmatrixContributor chain.

4. Handle weights (W)
------------------------
Currently W lives in WorkspaceLinear and is used by GramEvaluator to
compute A^T W A. With the structured path:

  D + UU^T  where  U = sqrt(W) * A^T

Or equivalently: D + A^T W A, where D absorbs any diagonal contribution
and U = (sqrt(W) * A)^T.

For the initial implementation, W = I (unweighted least squares).
Weighted case: the data source multiplies A by sqrt(W) before writing.
This keeps the subsystem unchanged.

5. Cleanup: remove dead code from structured path
-----------------------------------------------------
Once the structured path works end-to-end, for cliques that use it:
- No WorkspaceLinear allocation
- No GramEvaluator
- No LazySymmetricMatrix dispatch
- No SubmatrixContributor::WriteSymmetricLazy
- No Constraint::workspace() / do_get_workspace()

These stay for the dense fallback (total_rank >= n). Eventually, if
all LS cliques use the structured path, LinearConstraint can be
simplified to just (A, b, variables) with no workspace/evaluator.

6. Remove GetLazyEvaluator from base classes
------------------------------------------------
GetLazyEvaluator on SupernodalAssemblerBase and Constraint is only
needed for the dense path. Move it into the dense-specific adapter.
Base interfaces become: variables(), get_cliques(), Decompose().

Ordering: 1 -> 2 -> 3 -> 4 -> 5 -> 6


Problem/Solver Refactor Plan
============================
Goal: Replace ConstraintManager with Problem + Solver architecture.
Focus: Least squares algorithm first, then generalize.

Phase 1: Problem class
-----------------------
- [ ] Create conex/common/problem.h
- [ ] ConstraintId = int handle returned by Add* methods
- [ ] AddLinearConstraint(A, b, vars) → ConstraintId
- [ ] AddQuadraticCost(Q, vars) → ConstraintId
- [ ] AddEqualityConstraint(C, d, primal_vars, dual_vars) → ConstraintId
- [ ] Data only — no tree structure, no solver details

Phase 2: Solver class
-----------------------
- [ ] Create conex/common/solver.h
- [ ] MakeSolver(problem, config) → Solver (automatic tree via AMD)
- [ ] MakeSolver(problem, tree_spec, config) → Solver (custom tree)
- [ ] Internally: creates assemblers, runs clique ordering, calls Finalize
- [ ] Maps ConstraintId → per-clique evaluators + block info
- [ ] SetWeights(constraint_id, weights)
- [ ] ComputeResidual(constraint_id, BlockVariable) → VectorXd
- [ ] ComputeTransposeProduct(constraint_id, v) → BlockVariable
- [ ] MakeBlockVariable() / SolveInto() from underlying tree solver
- [ ] AssembleAndFactor() from underlying tree solver

Phase 3: Standalone Preprocess
-------------------------------
- [ ] Extract Preprocess from ConstraintManager into standalone function

- [ ] Expansion.Expand(x) maps reduced solution back

Phase 4: TreeSpec (custom tree)

Phase 5: Least squares via Problem + Solver

Phase 6: Tests
