Tree Solver Refactoring Plan: Structured Subsystem Support
==========================================================

Goal: Allow the tree solver to exploit structure (diagonal + low-rank)
in supernode blocks instead of always using dense factorization.
For sparse least-squares, every constraint A contributes A^T A which
is rank-m, so cliques can be factored in O(n*r^2) instead of O(n^3).

Current state (done):
- LowRankPlusDiagonalSubsystem: Woodbury-based factor/solve for D + UU^T
- LowRankDiagonalAdapter: bypasses lazy evaluator, writes d/U directly
- LowRankDiagonalDataSource: interface for providing d/U data
- UpdateData() and variables() are virtual on the adapter base class
- Tests pass for single-clique solve, Schur complement, adapter path

Key design principle:
  Providers describe their own contributions in their own natural format.
  The tree solver mediates: it collects contributions per clique, picks
  a subsystem type, and translates. Providers never see subsystem types.

Architecture:

  Provider            Tree Solver              Subsystem
  --------            -----------              ---------
  "I have A (m x n)   Collects per clique:     LowRankPlusDiagonal:
   on variables v"     stacks A^T into U,       stores D + UU^T,
                       picks subsystem type      factors via Woodbury

  Provider is just:
    variables() -> which variables
    rows()      -> rank of my contribution (= rows of A)
    WriteRows(dest, start_row, elim_positions) -> write A into a slot

  The provider does NOT know about D, U, subsystems, or Woodbury.
  The tree solver does the stacking: U = [A1^T | A2^T | A3^T].

Subsystem selection per clique:
  total_rank = sum of provider.rows() for all providers in this clique
  n = clique size (supernodes)
  if total_rank < n:
    Use LowRankPlusDiagonalSubsystem (O(n * r^2) factorization)
  else:
    Fall back to dense (current LLT/RLDLT path, O(n^3))

  The crossover is automatic — no per-provider "am I dense or structured?"
  flag needed. A single large constraint that fills the whole clique
  naturally triggers the dense fallback.

Remaining work:

1. Provider interface
------------------------
New interface for least-squares contributions:

  class IConstraintProvider {
    virtual std::vector<int> variables() const = 0;
    virtual int rows() const = 0;
    virtual void WriteRows(Eigen::Ref<MatrixXd> dest,
                           const std::vector<int>& elim_positions) const = 0;
  };

WriteRows writes the constraint matrix A (m x n_clique) into dest,
reordered to elimination order. The tree solver calls this during
UpdateData to populate U in the subsystem.

LinearConstraint implements this: WriteRows just copies A (possibly
reordered by elim_positions).

2. Tree solver stacking logic
---------------------------------
In UpdateAssemblerData (or a new structured equivalent):
  For each clique with structured providers:
    auto& sys = clique's LowRankPlusDiagonalSubsystem;
    sys.diagonal().setZero();        // or add regularization
    sys.low_rank_factor().setZero();
    int col = 0;
    for (auto* provider : providers_for_clique) {
      // provider writes A into U.block(0, col, n, provider->rows())^T
      provider->WriteRows(U_block, elim_positions);
      col += provider->rows();
    }

The tree solver owns this loop. Providers just write rows.

3. Subsystem creation
------------------------
During Finalize, per clique:
  total_rank = sum of rows across providers
  n = supernode size
  if total_rank < n:
    create LowRankPlusDiagonalSubsystem
    pre-allocate U as (n x total_rank)
  else:
    create LLTSolver / DynamicSubsystem (current path)

No CreateSubsystem() on the provider — the tree solver decides.

4. Wire into SparseLinearConstraint pipeline
------------------------------------------------
Currently: SparseLinearConstraintAssembler::Decompose() creates
LinearConstraint objects -> lazy evaluator -> dense subsystem.

Change: Decompose() creates IConstraintProvider objects instead.
Each holds its A block and variable list. The tree solver factory
(MakeTreeSolver) collects them, computes total rank per clique,
and creates the appropriate subsystem.

For A of size m x n_clique: contribution is A^T A = (A^T)(A^T)^T,
so U = A^T (n_clique x m). Provider just writes A; tree solver
transposes into U.

5. Refactor class hierarchy (deferred)
-----------------------------------------
Current: SupernodalAssemblerBase -> Constraint -> LinearConstraint
         KKTAssemblerToSubsystemAdapter + SubmatrixContributor

Target:
  ICliqueProblem        -- variables(), get_cliques(), Decompose()
  IConstraintProvider   -- rows(), WriteRows()
  LinearConstraint      -- implements both
  SubmatrixContributor  -- internal to dense fallback path only

The lazy evaluator path (GetLazyEvaluator, WriteSymmetricLazy,
SubmatrixContributor) stays as the dense fallback but moves out of
the base interfaces.

6. Remove GetLazyEvaluator from assembler base
--------------------------------------------------
Once the structured path handles the common case, GetLazyEvaluator
becomes internal to the dense fallback adapter. Not on any base class.

Ordering: 1 -> 3 -> 4 -> 2 -> 5 -> 6
(Provider interface first since it's new and isolated. Then subsystem
creation and pipeline wiring. Hierarchy refactor last.)
